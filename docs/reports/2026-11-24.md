## Decided

- The platform configures the endpoint: no deployer-supplied SAN or external URL, since Railway
  tells the service its own proxy hostname and port at runtime. A template therefore needs only two
  secrets from the person deploying it.
- Railway's Infrastructure as Code is not adopted yet: its reference documents neither the TCP proxy
  nor the Dockerfile path as of today, and its generally available TypeScript path needs Node.js for
  the SDK (Python and Go authoring are in beta). The runbook uses plain CLI commands, which cover
  everything.
- The first deploy uploads the working tree (`railway up`) and connects the GitHub source afterwards,
  so the GitHub app installation is not on the critical path of the first boot.

## Found

- Railway's SIGTERM-to-SIGKILL window defaults to 0 s. Without `RAILWAY_DEPLOYMENT_DRAINING_SECONDS`
  every redeploy would kill etcd mid-shutdown; the supervisor now warns and the runbook sets 60.
- The exported kubeconfig used `CP_APISERVER_PORT` for its URL even when a proxy sits in front, so
  on Railway it would have pointed at the wrong port unless `CP_EXTERNAL_URL` was set by hand. The
  proxy port now flows in from the platform.
- Installing a downloaded binary into `PATH` is refused by this session's safety policy; the CLI
  install and the device-code login are the person's steps.
- Review (architecture): the first draft only warned when an explicit SAN list lacked the proxy
  host, then wrote a kubeconfig pointing at that host anyway; the proxy host is a platform fact and
  is now always appended. The volume-path warning ran after the persistence check that would already
  have failed on it; it now runs first, with the fix in the message, and accepts a state root under
  the mount. A non-numeric proxy port fell through silently to the API server's own port; it warns.
- Review (security): the proxy hostname went unvalidated into the certificate's SAN list and the
  kubeconfig; it must now be a plain hostname. Neither ignore file excluded kubeconfigs, keys or
  `.env` files (a Phase 1 supply-chain note); both do now, and the runbook downloads the kubeconfig
  under `.work/`.
- Review (architecture, checked by test): Railway's template example for a base64 key,
  `secret(43, ...)` plus `=`, yields a non-canonical last character three times in four. GNU
  `base64 -d` still emits the 32 bytes but exits non-zero, and the image's `key_ok` counts bytes only,
  so the key is accepted; the runbook gives the strictly canonical construction anyway.
- Review (factual): "needs only two secrets" overstated it (three ordinary settings too); the
  Config-as-Code cutoff was no reason not to adopt IaC in a repository that never used it; the CLI
  commands were checked against the reference but have not been run, which the runbook now says.
