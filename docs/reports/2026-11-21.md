## Decided

- **Roadmap decision 4, where the control plane lives**: in this repository under
  `cluster/images/control-plane/`. A Railway service can build from a subdirectory, so the separate
  repository the 2026-08 handoff planned is not needed. Branch `phase-1/control-plane-image` is kept
  as history.
- **End goal clarified**: Hermes AI agents run as workloads inside DigitalOcean Kubernetes clusters
  that the Railway-hosted control plane provisions; the user's Railway app reaches them there. Hermes
  does not run on Railway, so this provider's job stays narrow (the control-plane service and the
  user app). This keeps the roadmap order: Phase 2 next, Hermes as a workload XRD at the end of Phase 3.
- **Terraform provider version**: stay on 0.6.2 plus patch for Phase 2. The 0.6.3 additions
  (`start_command`, health check, restart policy, `target_port`) are useful but not gating now that
  Hermes is not a Railway service.
- **Slack**: `#railway-upjet-provider` is the pipeline channel; changing it means editing `CLAUDE.md`.

## Summary

The first Phase 2 change lands the fix for the Phase 1 review's top finding: the control plane now
keeps etcd data, the PKI and a version stamp under one persistent state root, so a redeploy keeps
the cluster identity together with its data.

## Decided

- Caches (`xpkg`, `xfn`, Terraform plugin cache) stay on the ephemeral filesystem; only identity and
  data persist. Kubeconfigs are regenerated every boot from the persisted PKI.
- No migration from the Phase 1 layout; a volume at `/var/lib/etcd` is not adopted. Nothing was
  deployed, so nothing is lost.
- `CP_ADMIN_TOKEN` semantics: set to rotate, unset keeps the stored token; minimum 32 characters of
  `[A-Za-z0-9._-]`. Previously it only seeded the first boot and accepted any string.
- The version stamp is a high-water mark: an accepted downgrade does not lower it.

## Found

- The first draft rewrote the stamp unconditionally, so a boot with a missing binary or with the
  override set would have lowered it and disarmed the guard. Found in review; fixed.
- The Makefile had a comment on the `STATE_DIR` assignment line, which Make keeps as trailing spaces
  in the value and would have mounted the volume at the wrong path. Found in review; fixed.
- A forgotten volume mount was undetectable: the state root silently landed on the ephemeral layer.
  Found in review; `CP_REQUIRE_PERSISTENT` added.
- Co-locating `ca.key` with etcd data widens what a volume snapshot exposes. Accepted for Phase 2;
  B3 (encryption provider, etcd client auth, shorter credentials) is the mitigation.
